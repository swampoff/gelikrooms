# GelikRooms Admin | Hand-off для разработки

## 1. UI и дизайн-система

- Роль: администратор апартаментов, менеджер по размещению, управляющий.
- Desktop: тёмно-синий вертикальный сайдбар и светлая область управления.
- Mobile: фиксированная нижняя навигация на 5 разделов, плавающая кнопка создания брони; остальные разделы в мобильном меню.
- Цвета: midnight `#102737`, ocean `#167F83`, gold `#B88C59`, mint `#C5E9DF`, background `#F6F8F8`, ink `#162932`.
- Радиусы: карточки 17-20px, кнопки 9-12px, формы 9px.
- Типографика: Manrope с запасным системным sans-serif, для акцентного курсива Georgia.
- Контрольные ширины: 1440px, 1024px, 768px, 390px и 320px.
- Использовать реальные, оптимизированные изображения только после получения прав и оригиналов.

## 4. Правила безопасности перед production

1. Серверная аутентификация и RBAC для администратора, менеджера, бухгалтера.
2. При проверке пересечений активных броней использовать транзакцию и механизм блокировок на сервере: клиентская валидация не гарантирует отсутствие двойного бронирования.
3. Учёт оплат отдельными проводками, а не редактируемым числом `paid`.
4. Журнал изменений цен, дат, статусов и отмен; защита от случайного удаления.
5. Персональные данные гостей хранить только в защищённой базе, с ограничением доступа и сроками хранения.
6. Обязательное тестирование планшета, клавиатурной доступности, плохой сети и offline ошибок.
7. Выделить test / staging / production окружения; не перезаписывать действующие бронирования.

## 5. Интеграция

Проект сейчас не подключён к gelikrooms.ru и не влияет на настоящий сайт. При интеграции выяснить существующий стек, базу и API, затем заменить `seed()/localStorage` на модуль доступа к API, сохранив UI-компоненты и CSS. Уточнить внутренние правила расчёта стоимости и каналов продаж.

## 6. Ограничения демо

Имена объектов, гостевые записи, суммы и отзывы вымышлены. График выручки иллюстративный. Кнопка «Оплачено полностью» меняет только локальный объект; настоящего платежа нет. Ответы гостям не доставляются. Это важно сохранять явно помеченным до серверной интеграции.

## 7. Изменения v2

- Добавлены клиентские объекты `tasks` и `blocks` со списками и мобильными формами.
- Добавление апартаментов без сервера, блокировки и задачи хранятся локально.
- Диапазоны дат полуоткрытые: дата выезда не считается занятой ночью; `start < end`.
- Оплаченные суммы на графике сгруппированы по месяцу **заезда**, потому что фактические даты транзакций в демо не хранятся.
- Резервная копия JSON имеет `schema: gelikrooms.demo.v2`; импорт проверяет структуру и отсутствие пересечений, однако **не является безопасным механизмом переноса реальных данных**.
- До production обязательно реализовать авторизацию, журнал изменений, отдельную модель проводок, API для задач и блокировок и серверную проверку конкурентных операций.
